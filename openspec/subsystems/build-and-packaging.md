# Build And Packaging

## Purpose
Capture verified build/packaging behavior for native integration planning.

## Scope
Autotools project build, produced artifacts, dependency expectations, and compile-time options. CI workflow references are recorded separately as automation evidence.

## Evidence Used
- `configure.ac`
- `Makefile.am`
- `cov_build.sh`
- `.github/workflows/native_full_build.yml`

## Facts
- The project SHALL use autotools/libtool (`AC_INIT`, `AM_INIT_AUTOMAKE`, `LT_INIT`, `AM_PROG_LIBTOOL`).
- Build configuration SHALL enable shared and disable static (`AC_ENABLE_SHARED`, `AC_DISABLE_STATIC`).
- Build target SHALL define `libbreakpadwrapper.la` from `breakpad_wrapper.cpp` (`Makefile.am`).
- Build flags SHALL include `-fPIC` and C++ standard setting (`-std=c++0x`) in `AM_CXXFLAGS`.
- Build configuration SHALL support debug compile mode through `--enable-debug` mapping to `-D_DEBUG_` (`configure.ac`).
- `cov_build.sh` SHALL clone Google Breakpad and linux-syscall-support and build wrapper with `CXXFLAGS` include path to Breakpad headers.

## CI Automation Evidence (Non-Contract)
- `.github/workflows/native_full_build.yml` configures a repository workflow that runs `cov_build.sh` on pull requests to `develop`.

## Inferences
- Runtime artifact SHOULD include shared object(s) generated by libtool for target platform (for Linux typically `.so` symlink set).
- Packaging SHOULD rely on external provisioning of Breakpad headers/libs or include path setup equivalent to `cov_build.sh`.

## Unknowns / Manual Validation Needed
- Header installation rule is unclear; `Makefile.am` does not define `include_HEADERS`.
- Exact runtime linking dependencies to Breakpad libraries are not explicitly declared in top-level `Makefile.am`.
- Distribution packaging metadata (versioned SONAME, package split, dev package) is not visible in repository.
